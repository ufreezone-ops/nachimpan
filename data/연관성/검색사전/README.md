# 나침반 검색사전 (초안)

## 목적
검색어와 자료 사이에 사람이 확인할 수 있는 의미 연결층을 둔다. 외부 AI API 없이도 동의어·개념관계·예상 질문을 이용해 검색어를 확장할 수 있도록 설계한다.

## 파일 구성
- `예상_QA_검색확장.csv`: 사용자가 물을 법한 질문, 질문 의도, 핵심개념, 확장검색어, 기대 자료를 모은 검색 지식의 시드(seed). 질문은 실제 답변을 단정하는 FAQ가 아니라 검색 경로를 설계하는 입력이다.
- `동의어_사전.csv`: 같은 개념 또는 거의 같은 표현의 표기·구어체·설명형 변형. 주제상 관련이 있다는 이유만으로 동의어로 등록하지 않는다.
- `개념관계_사전.csv`: 서로 다른 개념 사이의 구성요소·부담주체·자금조달·분석차원·인과/영향·방법론 관계. 동의어와 구별한다.
- `검색검증_질문.csv`: 검색사전 구축에 직접 사용하지 않는 별도 검증 질문. 질문의 표현을 외운 결과가 아니라 검색 로직의 일반화 성능을 점검한다.

## 설계 원칙
1. 모든 자료 ID는 `나침반_자료분류_마스터.csv`의 resource_id를 사용한다.
2. 각 확장어·관계에는 근거와 기대자료 ID를 기록한다.
3. 가중치는 초기 제안값이며 검색 정확도를 의미하는 확률이 아니다.
4. 현재 모든 항목은 `초안_검토필요` 상태다. 자동으로 확정 사전에 편입하지 않는다.
5. Q&A의 답변범위는 해당 자료가 다룰 주제를 설명할 뿐, 수치·사실 답변을 대신하지 않는다. 실제 답변은 원자료와 보고서 내용을 확인해 작성한다.
6. 검색검증 질문은 QA 시드와 문구가 겹치지 않도록 분리한다. 기대자료는 정답 하나만 강제하지 않고 관련 자료 묶음으로 평가한다.
7. 원자료 XLSX는 검색 대상에서 제외한다. 다만 마스터 원장의 자료 관계를 통해 대응하는 추출 CSV를 찾을 수 있다.
8. 검색어 확장은 점수 가중치와 함께 사용한다. 개념 관계의 무분별한 확장으로 검색 결과가 과도하게 넓어지지 않도록 관계 유형별 가중치와 확장 깊이를 제한한다.

## 초안 현황
- 예상 Q&A: 40건
- 동의어 후보: 85건
- 개념 관계 후보: 42건
- 독립 검색 검증 질문: 20건

## 주의
이 버전은 2026-11-25 기준 dev 브랜치의 자료 분류 마스터와 확인한 CSV 헤더·샘플, 보고서 간 연관성 평가 구조를 바탕으로 만든 1차 초안이다. 용어의 동의어 여부, 관계 방향, 자료 적합성은 실제 검색 결과를 보며 검토해야 한다.

## 연결창 검색엔진 반영 (1차)
- `nachimpan_app.py`의 연결창 전체 검색이 이 폴더의 CSV 사전을 읽도록 연결되었다.
- `예상_QA_검색확장.csv`는 질문·의도·핵심개념·확장검색어가 함께 맞는 경우 기대자료ID를 검색 후보에 연결한다. 질문 문구 하나만 일치한다고 자료를 강제로 상위에 올리지는 않는다.
- `동의어_사전.csv`는 질문에 등장한 대표표현 또는 대체표현을 기준으로 양방향 확장한다.
- `개념관계_사전.csv`는 질문에 등장한 개념에서 한 단계만 확장한다. 관계어의 재귀 확장은 하지 않는다.
- 원문 검색어가 가장 높은 가중치를 갖고, 동의어와 개념관계는 낮은 보조 가중치를 갖는다. Q&A의 기대자료 연결도 제한적인 보너스로만 사용한다.
- 자료 ID는 연결창 검색 인덱스 및 마스터 원장의 resource_id/source_id 연결을 통해 실제 보고서·CSV 자료로 변환한다.
- 사전 파일이 없거나 읽기에 실패해도 기존 원문 검색은 중단되지 않는다. UTF-8 계열을 우선 읽고, 필요하면 CP949를 시도한다.
- `검색검증_질문.csv`는 검색엔진에 학습 입력으로 넣지 않는다. 검색 결과를 평가할 때 사용하는 독립 검증 세트다.

## 현재 검증 단계
- 검색엔진과 CSV 사전의 런타임 연결은 완료한 1차 구현이다.
- 실제 Streamlit 실행환경에서 20개 검증 질문의 상위 결과를 확인하고, 동의어·관계 가중치를 조정하는 작업은 다음 검증 단계로 남아 있다.
- 따라서 현재 사전 항목의 `초안_검토필요` 상태는 유지한다. 이번 코드 연결만으로 후보 표현이나 관계를 확정하지 않는다.

## 1차 검색엔진 연결 및 다중 의도 검색

- 연결창 검색은 질문을 정규화한 뒤 원문·동의어·개념관계·예상 Q&A를 함께 활용한다.
- 한 질문에 여러 생애 사건이 들어오면 QA의 예상질문·질문의도·핵심개념·확장검색어를 비교해 각각의 기대자료를 후보에 포함한다.
- 확장검색어 한 단어만 우연히 겹치는 QA는 오탐을 줄이기 위해 제외한다. 단일 개념은 QA의 예상질문·질문의도·핵심개념에도 등장할 때 연결한다.
- QA와 개념관계의 기대자료 ID는 마스터 원장의 `resource_id`와 `source_id`를 직접 매핑해 보고서와 CSV 자료 양쪽에 연결한다.
- 검색 결과에는 사용자가 이해할 수 있도록 매칭된 주제 표현을 '연결 근거'로 간단히 표시한다.
- 검색 검증 질문 20개를 이용한 실제 앱 런타임의 상위 결과 검증과 가중치 조정은 별도 검증 단계로 남겨 둔다.

## 복합 개념 띄어쓰기 보정 (2026-11-25)

- 검색어 토큰은 원래 단어를 보존하면서 인접한 두 토큰을 결합한 복합어 후보도 생성한다. 예를 들어 `경력 단절`은 `경력`, `단절`, `경력단절`로 비교한다.
- 동의어·개념관계 사전의 표현은 질문과 비교할 때 공백·문장부호를 제거한 형태도 확인한다. 따라서 `경력 단절`과 사전의 `경력단절`이 같은 개념으로 연결된다.
- QA 매칭에서는 `단절`처럼 여러 맥락에서 단독으로 쓰이는 일반 구성어 하나만으로 의도를 판정하지 않는다. `경력단절`과 `소득단절`처럼 복합 개념을 구분해 비교한다.
- 사용자 재현 질문 `결혼 과 출산, 그리고 경력 단절 에 대한 자료 를 알려줘`를 대상으로 정적 로직 검증을 수행했다. QA-017이 `출산`과 `경력단절`을 함께 매칭하고, QA-006은 `단절` 한 단어만으로 매칭되지 않는 것을 확인했다.
- QA-017의 기대자료 `NCH-0017`은 마스터 원장에서 보고서 source_id `6051800-00`으로 연결되어 있으며, 해당 보고서 분기와 검색 인덱스 수집 구조도 확인했다.
- 위 검증은 코드·사전·마스터 원장을 이용한 정적 검증이다. 실제 Streamlit 앱에서의 검색 결과 표시와 상위 순위는 dev 앱에서 별도로 확인해야 한다.

## 다중 주제 검색 결과의 후보 보장 및 표시 수 (2026-11-25)

- QA 사전이 특정 자료 ID를 지정했으나 보고서 AST 색인에서 해당 보고서가 누락된 경우, 마스터 원장의 resource_id·source_id를 이용해 최소 검색 후보 문서를 보완한다. 본문 색인 누락과 자료 ID 연결 실패를 분리한다.
- 여러 주제가 포함된 질문은 직접 검색 주제별로 관련 근거가 있는 자료를 우선 확보한 뒤 나머지를 점수순으로 채운다.
- 연결창 검색 결과는 최대 8건까지 제시한다. 3건으로 고정하지 않고, 검색어와 관련 자료가 충분하면 5건 이상 탐색할 수 있도록 한다.
- 여러 주제 질문에서는 직접 검색 주제별 관련 자료를 우선 확보한 뒤, 남은 자리를 전체 관련성 점수순으로 채운다. 특정 주제당 한 건으로 제한하지 않는다.
- 사용자 재현 질문의 핵심 주제는 결혼·출산·경력단절이며, 각 주제의 관련 자료를 우선 배치하되 추가로 연관된 자료도 함께 제시한다.

## 연결 근거 표현 정밀화 (2026-11-25)

- 검색 순위·후보 확장에 사용하는 합성 복합어와 화면에 표시하는 연결 근거 표현을 분리한다.
- 검색어의 인접 토큰 결합형은 검색 매칭에 계속 활용하되, 연결 근거에는 동의어·QA 핵심개념/확장검색어·개념관계에 독립 개념으로 등록된 복합어만 표시한다.
- 예를 들어 `경력 단절`은 사전에 등록된 `경력단절` 개념으로 표시할 수 있지만, 질문의 `결혼`과 `출산`이 단지 인접해 있다는 이유로 합성된 `결혼출산`은 별도 근거 표현으로 표시하지 않는다.
- `경력단절`이 연결 근거에 포함되면 구성어 `단절`은 중복 표시하지 않는다.
- 이 변경은 검색 점수 산식과 최대 8건 정책은 유지하면서, 화면에 표시하는 근거와 주제별 우선 선택 기준을 정교화한다. 합성어만 근거로 잡히던 자료는 주제별 우선 배치에서 제외될 수 있지만, 전체 점수순 보충 단계에서 여전히 결과 후보가 된다.
- 재현 질문의 정적 검증 결과: 검색용 direct terms는 `결혼`, `출산`, `경력`, `단절`, `결혼출산`, `출산경력`, `경력단절`을 유지하고, 화면 근거 후보는 `결혼`, `출산`, `경력`, `경력단절`로 정리된다.
- 실제 dev 앱에서 표시되는 연결 근거는 사용자 화면으로 재확인해야 한다.
