# 나침반의 세계관

- 문서 성격: 나침반 UI·기능 설계의 상위 원칙
- 버전: 1.2
- 최초 정리일: 2026-11-22
- 적용 범위: 신규 UI, 창·버튼·나침반·자료 탐색 기능, 정보 구조 및 사용자 여정

## 1. 핵심 철학

나침반은 사용자가 자신의 삶과 생계수단, 인생의 사계절을 살펴보며 재정적 선택의 경계를 이해하도록 돕는 탐색 도구다. 정답을 대신 제시하기보다 현재 생각의 경계와 놓치고 있는 영역을 보여준다.

핵심 디자인 원칙은 **“그림책은 단순하게, 도서관은 빼곡하게.”** 이다. 처음 접하는 사용자는 부담 없이 큰 흐름을 훑어볼 수 있어야 하고, 더 알고 싶은 사용자는 충분한 근거·통계·보고서로 깊이 들어갈 수 있어야 한다.

## 2. 5+1개의 대륙: 자료 분류의 세계

자료는 성격에 따라 5+1개 유형으로 묶여 있으며, 각 유형은 판타지 게임의 대륙에 대응한다. 각 대륙에는 고유한 색상이 부여되고, 자료는 해당 분류 안에서 1, 2, 3…의 일련번호를 갖는다.

- 대륙의 구분과 색상은 자료의 정체성을 구별하는 내부 질서다.
- 같은 일련번호가 서로 다른 대륙에서 반복될 수 있으므로, 번호만으로 자료를 식별하지 않는다. 대륙 구분과 번호를 함께 사용해야 한다.
- 대륙은 현재 자료 수가 많지 않다는 이유로 UI 전면에 과도하게 드러내지 않는다.
- 사용자가 자료의 출처·분류를 알아야 하는 순간에는 색상과 분류 정보를 자연스럽게 제공한다.
- 대륙별 실제 명칭과 색상값은 별도의 분류·색상 기준표를 단일 기준으로 삼으며, 이 문서에서 임의로 새로 정하지 않는다.

## 3. 나침반: 훑어보기에서 깊이 보기로 가는 통로

사용자는 기본모드에서 인생의 사계절과 주요 흐름을 단순하게 훑어본다. 더 깊은 탐색을 원할 때 나침반 아이콘을 누르면 자료가 보이는 깊이 보기로 진입한다.

나침반은 단순한 장식 아이콘이 아니다.

- 탐색의 시작점이자 모드 전환의 통로다.
- 사용자가 현재 위치와 다음 방향을 이해하도록 돕는다.
- 자료 탐색 중에도 길을 잃지 않도록 복귀·이동 기능과 일관된 의미를 유지한다.
- 인생의 사계절을 살펴보는 화면과 자료 탐색 화면 모두에서 방향을 상징한다.

## 4. 지하철 2호선: 보이지 않는 자료 연결망

자료는 각각 고립된 문서가 아니라 서로 연결될 수 있는 그물망 구조를 가진다. 이 구조를 도심의 지하철, 특히 순환하는 서울 지하철 2호선의 비유로 설명한다.

- 사용자는 자료를 하나씩 읽고, 연관성 지수를 통해 다음 자료로 자연스럽게 이동할 수 있다.
- 연결은 단순한 목록 나열이 아니라 자료 사이의 관계를 따라가는 탐색 경험이다.
- 지하철 비유와 노선의 세계관은 내부 구조를 이해시키는 개념적 장치이며, 모든 화면에 노선도를 상시 노출하라는 뜻은 아니다.
- 추천 알고리즘과 자료 간 능동적 연계는 사용자에게 복잡성을 강요하지 않으면서 깊이 있는 탐색을 가능하게 해야 한다.

## 5. 보물지도와 도서관: 보고서와 통계

보고서는 탐험 중 발견하고 펼쳐보는 보물지도다. 통계 탭은 그 보물지도의 근거가 되는 자료가 빼곡히 축적된 도서관이다.

- 보고서는 사용자의 삶의 질문과 연결되는 이야기의 입구로 제시한다.
- 통계·원자료·출처는 깊이 있는 검토를 원하는 사용자가 찾아갈 수 있도록 보존한다.
- 통계 탭은 필요한 경우 살짝 뒤에 두어도 되지만, 자료의 근거와 출처에 접근할 길은 막지 않는다.
- 연결창에서 관련 자료를 훑어볼 수 있게 하여, 매번 통계 탭을 왕복해야 하는 불필요한 이동을 줄인다.

## 6. 기본모드와 고급모드: 두 단계의 탐험

### 기본모드

- 인터뷰이에게 인생의 사계절과 재정 흐름을 간결하게 보여준다.
- 처음부터 많은 통계와 자료를 노출하지 않는다.
- 인터뷰어가 기본모드만으로도 큰 흐름과 질문의 방향을 안내할 수 있어야 한다.

### 고급모드

- 인터뷰이의 관심과 자발적인 참여 의사를 바탕으로 진입한다.
- 보고서, 통계, 자료 간 연결과 추천을 활용해 더 깊이 탐색한다.
- 인터뷰어가 충분한 이해와 안내 역량을 갖추도록 대표사례를 교육용으로 제공한다.
- 대표사례에는 결혼·출산·주택·자녀 교육·은퇴 등 주요 생애 이벤트(빅5)가 반영된 소득·지출 그래프를 활용해 교육한다.

기본모드와 고급모드는 우열 관계가 아니라 서로 다른 깊이의 경험이다. 기본모드만으로도 의미 있는 안내가 가능해야 하며, 고급모드는 사용자가 원할 때 확장되는 선택지다.

## 7. 연결창과 자료창: 길을 잃지 않게 하는 탐색 도구

연결창과 자료창은 단순한 팝업이 아니라 탐험의 위치와 이동 경로를 보존하는 도구가 탑재된 작은 공간이다.

새 창을 열더라도 사용자는 다음을 잃지 않아야 한다.

1. 원래 어디에서 출발했는가?
2. 지금 어떤 자료·위치를 보고 있는가?
3. 이전 위치 또는 처음 탭으로 어떻게 돌아가는가?
4. 다음 자료로 어떻게 이동하는가?

창의 종류와 기능에 따라 닫기, 연결창으로 돌아가기, 처음 탭으로 돌아가기, 이전·다음 자료 이동 등 필요한 복귀 수단을 명확히 제공한다. 버튼의 명칭과 동작은 실제 이동 결과와 일치해야 한다.

## 8. 이중 3계층 구조와 인터페이스의 교차점

나침반은 서로 다른 방향의 두 3계층이 교차하는 구조다. 두 계층은 각각 씨실과 날실로 이해한다.

### 8.1 씨실: 정보와 탐색의 깊이

1. **그림책** — 기본모드와 고급모드에서 삶의 큰 흐름을 훑어본다.
2. **연결** — 연결창과 자료창을 통해 관련 자료를 탐색한다.
3. **도서관** — 통계자료실에서 근거·통계·보고서를 깊이 살펴본다.

### 8.2 날실: 공간과 이동의 깊이

1. **지상** — 그림책이 펼쳐지는 일상의 공간이다.
2. **연결** — 서울 지하철 2호선의 비유를 바탕으로 자료 사이를 이동하고 환승하는 공간이다.
3. **지하** — 5대륙으로 구분된 자료의 세계다.

### 8.3 크로스 포인트: 연결·연결창

씨실의 정보 탐색 계층과 날실의 공간 이동 계층은 **연결·연결창**을 크로스 포인트로 삼아 교차한다.

- 씨실에서 연결은 그림책과 도서관 사이를 잇는 정보 탐색의 계층이다.
- 날실에서 연결은 지상과 지하를 잇는 이동의 계층이며, 서울 지하철 2호선의 비유로 표현한다.
- 연결창은 두 계층이 실제 인터페이스와 사용자 경험 안에서 만나는 교차점이다.
- 두 축에 같은 이름인 ‘연결’이 등장하더라도 역할을 혼동하지 않는다. 하나는 정보의 깊이, 다른 하나는 공간과 이동의 깊이를 나타낸다.

## 9. 인터페이스의 최우선 원칙: 무엇을 보고 있고, 어디에 있는가

나침반 인터페이스를 설계하고 평가할 때 가장 중요한 기준은 인터뷰이가 **지금 무엇을 보고 있는지**, 그리고 **지금 어디에 있는지**를 명확히 이해할 수 있는가이다.

1. **무엇을 보고 있는가?** — 현재 보고 있는 정보·콘텐츠·자료가 무엇인지 분명해야 한다.
2. **어디에 있는가?** — 현재 탐색 공간과 위치가 무엇인지 분명해야 한다.
3. **어디로 갈 수 있는가?** — 다음 이동 경로와 선택지는 탐색을 돕는 보조 정보다.
4. **어떻게 돌아오는가?** — 출발 위치와 복귀 경로를 잃지 않게 하는 것도 보조 기능이다.

앞의 두 기준이 인터페이스의 본질이며, 뒤의 두 기준은 사용자의 탐색을 지원한다. 씨실과 날실의 계층, 색상, 지하철 2호선, 5대륙, 장식과 기타 세계관 요소는 모두 이 본질을 이해하고 유지하도록 돕는 보조 수단이다.

- 세계관이나 시각적 장치 자체가 사용자의 시선을 빼앗거나 현재 위치와 콘텐츠를 혼동하게 해서는 안 된다.
- 색상·장식·상징이 아름답더라도 인터뷰이가 무엇을 보고 있고 어디에 있는지 파악하기 어렵게 만든다면 잘못된 설계다.
- 화면과 창을 설계하거나 수정할 때는 먼저 현재 콘텐츠와 현재 위치가 즉시 식별되는지 확인한다. 그 다음에 이동·복귀 기능과 시각적 보조 요소를 검토한다.
- 나침반은 인터뷰이에게 세계관을 설명하는 인터페이스가 아니라, 인터뷰이가 자신의 시선과 위치를 잃지 않도록 돕는 인터페이스다.

## 10. UI 디자인 원칙

### 8.1 스마트폰 세로 화면 우선

- 주요 사용 환경인 스마트폰 세로 화면을 기준으로 설계하고 검토한다.
- 가로 폭은 콘텐츠에 최대한 할애하며 좌우 장식과 두꺼운 테두리는 최소화한다.
- 상단과 하단의 절제된 장식으로 창의 완성도를 높인다.
- 글자, 버튼, 스크롤, 닫기·복귀 동작은 작은 화면에서 편안하고 명확해야 한다.
- PC 화면은 스마트폰 경험을 해치지 않는 범위에서 확장 대응한다.

### 8.2 창의 공통 외형과 색상 체계

창은 공통 디자인 언어를 공유하되, 기능별 구조를 억지로 하나로 통합하지 않는다.

- 공통 바탕은 아이보리 계열의 차분하고 따뜻한 분위기를 기본으로 한다. 오래된 지도책의 종이 같은 온기는 배경의 색조와 질감으로 은은하게 표현할 수 있다.
- 서울 지하철 2호선의 녹색은 자료 사이의 연결과 이동을 나타내는 색상으로 활용한다.
- 5개 대륙의 고유 색상은 자료의 소속과 정체성을 식별하는 데 사용한다. 창 전체의 배경색으로 과도하게 확장하지 않는다.
- 나침반 아이콘의 기존 색상 정체성을 존중하며, 창의 색상 체계와 조화를 이루도록 한다.
- 실행 동작에는 앱에서 이미 사용 중인 주황색 등 기존 의미 색상을 일관되게 사용한다.
- 색상은 서로 경쟁하지 않도록 역할을 구분한다. 창의 바탕, 연결·이동, 자료 분류, 실행 동작의 색상 의미를 혼용하지 않는다.

### 8.3 창의 공간 구성: 좌우 개방과 상하 장식

창의 디자인은 액자처럼 콘텐츠를 둘러싸는 방식이 아니라, 콘텐츠가 넓게 펼쳐지는 공간을 만드는 방식으로 설계한다.

- 좌우에는 디자인 목적의 장식 요소를 두지 않는다. 좌우 테두리, 기둥, 액자 프레임, 장식선 등은 사용하지 않는다.
- 창의 시각적 정체성을 표현하는 장식은 상단과 하단에만 절제해 배치한다.
- 상단·하단 장식도 콘텐츠를 가리거나 사용 가능한 영역을 침범해서는 안 된다. 필요한 경우 콘텐츠보다 뒤쪽 레이어에 배치한다.
- 배경은 분위기를 만드는 후면 요소다. 콘텐츠 위에 덮이거나 가독성과 조작을 방해해서는 안 된다.
- 스마트폰 세로 화면에서 콘텐츠의 좌우 폭을 최대한 확보한다. 장식이나 컨테이너의 기본 여백 때문에 유효 폭이 불필요하게 줄어들지 않도록 한다.
- 장식의 완성도보다 콘텐츠의 가로 공간과 가독성을 우선한다.

### 8.4 콘텐츠 여백과 내어쓰기 계층구조

콘텐츠 영역의 여백·마진·패딩·경계선은 일률적으로 제거하지 않는다. 내용의 위계와 가독성을 위해 필요한 만큼만 사용한다. 특히 내부창이나 중첩 컨테이너가 열릴 때 여백과 경계가 누적되어 콘텐츠 폭을 잠식하지 않도록 한다.

나침반은 일반적인 들여쓰기 계층구조와 반대로, **제목은 안쪽으로 들이고 본문은 바깥으로 내어 확장하는 계층구조**를 기본 방향으로 삼는다.

- 제목·소제목 등 구조를 알려주는 요소에는 의도적인 좌우 들여쓰기를 줄 수 있다. 제목의 위치와 여백으로 정보의 위계를 표현한다.
- 본문·표·그래프·보고서 등 실제 정보를 담는 콘텐츠는 가능한 한 좌우 폭을 넓게 사용한다.
- 본문을 제목 안쪽으로 다시 들여써서 폭을 연속적으로 줄이지 않는다. 제목은 질서를 만들고, 본문은 공간을 확장한다.
- 내부창의 마진·패딩·경계선은 필요 여부를 개별 판단한다. 장식적 목적만 있는 여백과 경계는 생략하거나 최소화한다.
- 단, 내용 구분·가독성·터치 조작에 필요한 여백은 유지한다. 무조건 여백을 없애는 것이 목표가 아니다.
- 카드나 내부 패널을 중첩할 때마다 좌우 여백이 계단식으로 누적되지 않도록 한다. 필요한 구분은 배경 톤, 간격, 얇은 구분선 등 폭을 덜 차지하는 방법을 우선 검토한다.

### 8.5 기능별 구조와 구현 주의

- 탐색 기능: 현재 위치, 복귀 경로, 다음 이동을 명확히 한다.
- 콘텐츠 식별: 필요한 경우 대륙 고유 색상과 자료 번호를 활용한다.
- 연결창과 자료창 등 Streamlit 구성요소의 내부 구조 차이를 존중한다. 공통 CSS 적용으로 기존 기능·버튼 규격·위치가 깨지지 않도록 한다.
- 실제 구현에서는 각 구성요소의 DOM과 기본 padding·margin을 확인한 뒤 수정한다. 시각적으로 비슷하다는 이유만으로 서로 다른 구성요소의 CSS를 무리하게 통합하지 않는다.

### 8.6 세계관의 노출 수준

세계관을 매 화면에 설명하거나 장식으로 반복하지 않는다. 사용자가 길을 찾거나 자료의 성격을 구별해야 할 때 자연스럽게 드러나도록 한다. 세계관은 겉으로 복잡성을 더하는 장식이 아니라, 보이지 않는 곳에서 일관성과 질서를 지키는 설계 원칙이다.

## 11. 신규 UI·기능 추가 시 확인 사항

새 UI나 기능을 설계할 때 다음을 확인한다.

- 인터뷰이가 지금 무엇을 보고 있는지 즉시 알 수 있는가?
- 인터뷰이가 지금 어디에 있는지 즉시 알 수 있는가?
- 위 두 가지 본질을 해치지 않는 범위에서 다음 이동과 복귀 방법이 명확한가?
- 이 기능은 씨실(그림책-연결-도서관)과 날실(지상-연결-지하)의 어느 위치에 속하는가?
- 나침반을 통한 탐색 흐름과 자연스럽게 연결되는가?
- 대륙·자료 번호·색상 체계와 충돌하지 않는가?
- 자료 간 연결망과 연관성 기반 추천을 불필요하게 복잡하게 만들지 않는가?
- 사용자가 현재 위치와 원래 위치로 돌아갈 방법을 이해할 수 있는가?
- 스마트폰 세로 화면에서 읽고 조작하기 편한가?
- 그림책의 단순함을 해치지 않으면서 필요한 깊이를 제공하는가?
- 기존 버튼·나침반·창 표준 규격 및 메뉴얼과 일관되는가?

## 12. 문서 업데이트 원칙

이 문서는 나침반 UI와 기능 설계의 상위 참조 문서로 유지한다.

- 신규 UI 또는 기능을 추가할 때 먼저 이 문서와의 정합성을 확인한다.
- 세계관의 의미가 구체화되거나, 대륙·연결망·탐색 흐름이 확장되거나, 새로운 기능이 추가되면 관련 내용을 갱신한다.
- 단순 구현 세부사항은 해당 기능별 메뉴얼에 기록하고, 세계관에 영향을 주는 원칙과 변경사항만 이 문서에 반영한다.
- 업데이트 시 버전, 날짜, 변경 요약을 기록한다.
- 기존 원칙과 충돌하는 변경이 생기면 임의로 덮어쓰지 말고 변경 이유와 적용 범위를 명시한다.
