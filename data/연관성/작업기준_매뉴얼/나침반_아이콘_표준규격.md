# 나침반 아이콘 표준규격

- 관리번호: UI-002
- 상태: **적용 완료**
- 적용 기준 브랜치: `dev`
- 마지막 정리: 2026-11-21

## 1. 목적과 기본 원칙

이 매뉴얼은 나침반 아이콘을 화면의 제목에 붙이고, 그 제목과 나침반을 눌렀을 때 관련 보고서·자료·연결창으로 이동하도록 연결하는 방식을 기록한다.

나침반은 단순한 장식이 아니라 해당 제목의 이해에 필요한 자료를 찾아가는 탐색 수단이다. 따라서 모양만 맞추는 것이 아니라 다음 두 가지를 함께 적용한다.

1. **표시 방식:** 제목 문구 끝에 나침반 아이콘을 붙여 제목과 한 덩어리로 보이게 한다.
2. **연결 기능:** 제목이나 나침반 어느 부분을 눌러도 같은 기능이 실행되도록 하나의 버튼으로 구성하고, 기존 자료 ID·탐색 이력·복귀 위치를 보존한다.

기본 원칙은 다음과 같다.

- 제목과 나침반은 가능한 한 하나의 실제 버튼 안에 배치한다.
- 제목과 나침반은 같은 클릭 영역을 공유한다.
- 기존 나침반 표시인 유니코드 `🧭`를 사용한다.
- 운영체제별 이모지 렌더링 차이는 허용한다. PC와 iPhone에서 동일한 그림을 강제로 만들기 위해 별도 이미지로 대체하지 않는다.
- 별도 이미지 파일, CSS `::after` 배경 이미지 등으로 나침반을 중복 삽입하지 않는다.
- 기존 보고서 연결, 자료 ID, 탐색 이력, 복귀 위치는 변경 요청이 없는 한 그대로 보존한다.
- 제목 위계와 실제 DOM 구조를 확인한 뒤 대상별로 적용한다. 모든 제목에 포괄 CSS를 일괄 적용하지 않는다.

**작업 절차:** 대상 위치 확인 → 제목·나침반의 DOM 구조 확인 → 단일 버튼으로 통합 → 기존 연결 기능 확인 → PC·iPhone 화면 확인 → 매뉴얼 기록.

## 2. 나침반의 역할 분류

| 유형 | 역할 | 기본 검토 항목 |
|---|---|---|
| 제목 연결버튼 | 제목과 함께 배치되어 관련 자료·보고서로 이동 | 제목 위계, 제목과 아이콘의 통합 여부, 클릭 영역, 간격·수직 정렬 |
| 자료 연결 버튼 | 특정 자료·보고서·통계 또는 연결창으로 이동 | 클릭 대상, 자료 ID, 복귀 위치, 탐색 이력 |
| 메뉴·장식형 | 메뉴 정체성이나 화면 안내를 보조 | 장식과 실제 클릭 기능의 구분, 불필요한 클릭 오인 방지 |

## 3. 제목 연결버튼의 위계 구분

제목 연결버튼은 실제 화면의 제목 위계와 위치에 따라 다음과 같이 구분한다.

- 대제목
- 소제목
- 카드 제목
- 입력 항목

각 대상에서 확인할 사항:

1. 제목과 나침반이 같은 버튼 안에 있는가?
2. 제목과 나침반 모두 같은 클릭 기능을 실행하는가?
3. 제목의 위계에 맞는 글자 크기·굵기·간격·수직 정렬인가?
4. 버튼이 열어야 하는 보고서 또는 연결창의 source ID가 정확한가?
5. 닫기·이전 위치 복귀가 기존 위치로 정상 작동하는가?

## 4. 적용 사례 — 은퇴 후에는?

### 4.1 적용 위치와 코드 구조

- 화면: `우리집 가계부` 탭의 고급모드, 은퇴 후 가정 입력 패널
- 상위 블록: `6.01.05`
- 제목 행 key: `retirement-expense-title-row`
- 통합 제목·나침반 버튼 key: `retirement_expense_title_open`
- 연결 자료 source IDs: `6050400-01`, `6051400-00`, `6051300-00`

제목 문구와 나침반을 하나의 Streamlit 버튼 라벨로 구성한다.

현재 표시 문구:

```python
"은퇴 후에는? (만원) 🧭"
```

제목과 나침반은 동일한 버튼이며, 어느 부분을 눌러도 기존 연결창을 연다. 별도 나침반 버튼이나 이미지 렌더링을 추가하지 않는다.

### 4.2 제목 버튼 규격

| 항목 | 적용 기준 |
|---|---|
| 제목·나침반 표시 | 하나의 버튼 라벨 안에 제목과 `🧭` 배치 |
| 클릭 영역 | 제목과 나침반이 하나의 버튼을 공유 |
| 별도 이미지 | 사용하지 않음 |
| 연결 방식 | 기존 연결창 열기 |
| 자료 목록 | `6050400-01`, `6051400-00`, `6051300-00` |
| 복귀 위치 | `.st-key-retirement-expense-title-row button` |

제목 버튼의 글자 크기·굵기·높이·수직 정렬은 해당 화면의 제목 위계와 기존 CSS 규칙을 따른다. 다른 제목에 수치를 복사하기 전에 실제 DOM과 계산된 스타일을 확인한다.

### 4.3 이동 및 복귀 흐름

제목 또는 나침반을 누르면 기존 연결창을 연다.

1. 연결창 열기: `_retirement_connection_open = True`
2. 자료 목록: `6050400-01`, `6051400-00`, `6051300-00`
3. 최초 진입 탭: `selected_page` 값 보존
4. 복귀 anchor: `.st-key-retirement-expense-title-row button`
5. 기존 탐색기·자료 이력 상태 초기화 방식 유지

연결창을 닫으면 최초 진입 위치로 돌아온다.

## 5. 적용 사례 — 세대 계승 생애주기 재정곡선

### 5.1 적용 위치와 코드 구조

- 화면: `인생의 사계절` 탭
- 렌더러: `render_official_nta_section()`
- 상위 블록: `6.03.01.01`
- 제목 행 key: `nta-generational-title-row`
- 통합 제목·나침반 버튼 key: `nta_generational_title_open`
- 대표 보고서 source ID: `6051700-00`

제목 문구와 나침반을 하나의 Streamlit 버튼 라벨로 구성한다. 고급모드에서는 제목 끝에 `🧭`를 표시하고, 기본모드에서는 기존 표시 조건에 따라 제목만 표시한다.

### 5.2 제목 버튼 규격

| 항목 | 적용 기준 |
|---|---|
| 제목·나침반 표시 | 고급모드에서 하나의 버튼 라벨 안에 제목과 `🧭` 배치 |
| 클릭 영역 | 제목과 나침반이 하나의 버튼을 공유 |
| 별도 이미지 | 사용하지 않음 |
| 대표 보고서 source ID | `6051700-00` |
| 복귀 anchor | `.st-key-nta-generational-title-row` |

제목 버튼의 글자 크기·굵기·높이·수직 정렬은 첫 번째 제목 연결 사례와 동일한 기준을 적용하되, 실제 화면의 DOM 및 계산된 스타일을 기준으로 검증한다.

### 5.3 이동 및 복귀 흐름

제목 또는 나침반을 누르면 대표 보고서를 연다.

1. 대표 보고서 창 열기
2. 보고서 source ID를 `6051700-00`으로 설정
3. 탐색 이력을 해당 보고서에서 시작
4. 최초 진입 탭을 `인생의 사계절`로 기록
5. 복귀 anchor를 `.st-key-nta-generational-title-row`로 기록

대표 보고서 창의 `연결` 버튼은 기존 연결창을 연다. 연결창 또는 보고서 창을 닫으면 최초 진입 위치로 복귀한다. 차트 자체의 클릭 연결은 별도 기능이므로 제목 버튼의 동작과 혼동하지 않는다.

## 6. 적용·검증 현황

| 대상 | 제목+나침반 단일 버튼 | 기존 연결 기능 | 상태 |
|---|---|---|---|
| 은퇴 후에는? | 적용 | 기존 연결 자료 및 복귀 흐름 유지 | **적용 완료** |
| 세대 계승 생애주기 재정곡선 | 적용 | 대표 보고서·연결창·복귀 흐름 유지 | **적용 완료** |

화면에서 확인된 표시와 동작을 기준으로 두 항목 모두 적용 완료로 관리한다. 이후 다른 위치에 적용할 때도 다음 항목을 확인한다.

- [ ] 제목과 `🧭`가 하나의 버튼 안에 있는가?
- [ ] 제목과 나침반 어느 부분을 눌러도 동일하게 작동하는가?
- [ ] 정확한 보고서·자료 ID로 연결되는가?
- [ ] 연결창의 이전·다음 및 탐색 이력이 유지되는가?
- [ ] 닫기 후 최초 진입 위치로 돌아오는가?
- [ ] PC와 iPhone에서 제목·나침반의 간격과 수직 정렬이 자연스러운가?
- [ ] 별도 이미지나 중복 나침반이 삽입되지 않았는가?

## 7. 적용 시 유의사항

- 제목과 나침반은 하나의 버튼 라벨 안에 둔다.
- 별도 나침반 버튼이나 별도 이미지 요소를 추가하지 않는다.
- 제목과 나침반의 간격·수직 정렬은 실제 DOM과 브라우저 계산값을 확인해 조정한다.
- 대상별 보고서 ID와 복귀 위치는 기존 동작을 확인한 뒤 보존한다.
