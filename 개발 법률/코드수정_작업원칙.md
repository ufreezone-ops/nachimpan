# 코드 수정 작업 원칙

- 문서 성격: 나침반 개발헌법의 하위 법률
- 적용 대상: 나침반 소스코드를 작성·수정·검토하는 사람과 모든 AI 및 협업자
- 적용 범위: `dev` 브랜치의 신규 코드 작성, 기존 코드 수정, 코드 구조 정리 및 관련 검증
- 상위 규범: `나침반 개발헌법.md`
- 버전: 0.1
- 상태: 초안
- 최초 작성: 2026-11-22

> 이 법률은 개발헌법의 코드 작업 원칙을 실제 작업에서 실행할 수 있도록 구체화한다. 개발헌법과 충돌하는 경우 개발헌법을 우선한다.

## 제1조. 목적과 기본 원칙

1. 코드의 기능뿐 아니라 사람이 코드를 읽고, 위치를 찾고, 변경 영향을 이해할 수 있는 구조를 유지하는 것을 목적으로 한다.
2. 나침반 코드는 사람과 AI가 함께 이해하고 이어서 개발할 수 있어야 한다.
3. 코드의 위치와 책임은 행 번호가 아니라 블록 번호와 계층 구조로 식별한다.
4. **이 법률 시행 이후 새로 작성하거나 추가하는 모든 기능 코드는 블록 번호 체계를 적용해야 한다.**
5. 블록 번호가 없는 신규 코드는 작업 완료로 처리하지 않는다.
6. 기존 코드의 기능과 데이터 흐름을 보존하면서, 필요한 범위만 작고 명확하게 변경한다.

## 제2조. 블록의 계층과 의미

1. 블록의 계층은 다음 순서로 구분한다.
   - 블록
   - 하위 블록
   - 마이크로 블록
   - 나노 블록
2. 블록은 독립적인 기능 영역 또는 책임 영역을 나타낸다.
3. 하위 블록은 상위 블록 안에서 구분할 필요가 있는 기능 영역을 나타낸다.
4. 마이크로 블록은 코드 수정·검토·설명 시 독립적으로 지칭할 수 있는 구체적인 작업 단위를 나타낸다.
5. 나노 블록은 마이크로 블록 안에서 별도로 구분할 필요가 있는 세부 처리 단위에 사용한다.
6. 모든 코드에 네 단계의 블록을 기계적으로 만들 필요는 없다. 코드의 실제 책임과 규모에 맞춰 필요한 계층까지만 사용한다.
7. 블록은 단순히 줄 수를 나누기 위한 구분이 아니다. 하나의 블록은 가능한 한 하나의 분명한 목적과 책임을 가져야 한다.

## 제3조. 신규 코드의 블록 번호 부여

1. 신규 기능 또는 신규 코드 영역을 작성하기 전에 해당 코드가 속할 기존 상위 블록과 주변 번호 체계를 확인한다.
2. 기존 블록 안에 기능을 추가하는 경우에는 해당 기능의 성격에 맞는 하위 블록 또는 마이크로 블록을 새로 부여한다.
3. 하나의 블록에 서로 다른 책임의 기능이 추가되어 독립적인 수정·검토가 필요해지면 기능별로 구분된 하위 블록 또는 마이크로 블록을 부여한다.
4. 기존 상위 블록과 연결되지 않는 독립 기능은 파일 전체의 번호 체계와 충돌하지 않는 새 블록 번호를 부여한다.
5. 새 번호는 주변 블록의 실제 구조와 사용 중인 번호를 확인한 뒤 정한다. 번호를 추측하거나 기존 번호를 재사용해서는 안 된다.
6. 신규 코드의 시작 위치에는 해당 코드의 범위를 알아볼 수 있도록 블록 번호와 기능명을 주석으로 표시한다.
7. 블록 번호 주석은 해당 블록이 시작되는 위치에 두고, 코드의 실제 범위와 주석의 설명이 일치하도록 유지한다.
8. 기존 블록에 속하는 단순한 보완·오류 수정은 기존 블록 번호를 유지할 수 있다. 다만 별도의 책임을 가진 신규 기능을 추가하면서 기존 번호만 붙여 신규 기능의 위치를 숨겨서는 안 된다.
9. 번호 체계가 불분명하거나 적절한 번호를 결정할 근거가 부족하면 임의로 번호를 만들지 않는다. 작업을 멈추고 주변 구조와 선택 가능한 번호안을 사용자에게 제시한다.

## 제4조. 블록 번호의 보존과 변경

1. 기존에 부여된 블록 번호는 원칙적으로 유지한다.
2. 기존 블록의 코드 위치가 이동하거나 내부 코드가 수정되었다는 이유만으로 번호를 변경하지 않는다.
3. 블록을 분리·통합·이동하거나 번호를 변경해야 할 필요가 있으면 먼저 참조 관계와 영향 범위를 조사하고 사용자 승인을 받는다.
4. 사용이 끝난 번호를 새 기능에 임의로 재사용하지 않는다.
5. 블록 번호의 중복, 계층 역전, 상위·하위 관계의 모순이 발견되면 임의로 정리하지 말고 문제와 영향 범위를 보고한다.
6. 행 번호는 작업 중 임시 위치를 찾는 참고값으로만 사용하며, 문서·작업 지시·관리대장의 지속적인 식별 기준으로 삼지 않는다.

## 제5조. 기존 코드와 단계적 정비

1. 이 법률은 우선 신규 코드와 새로 추가되는 기능 코드에 엄격하게 적용한다.
2. 기존 코드 전체에 블록 번호를 한꺼번에 부여하거나 기존 번호 체계를 일괄 재편하지 않는다.
3. 기존에 블록 번호가 있는 코드를 수정할 때는 기존 번호와 구조를 우선 보존한다.
4. 기존에 블록 번호가 없는 영역을 수정하는 경우에도 새로 작성하거나 추가하는 코드에는 이 법률의 신규 코드 번호 규칙을 적용한다.
5. 기존 무번호 코드 전체를 정비할 필요가 있으면 신규 기능 작업과 분리된 별도 정비 과제로 제안한다.
6. 기존 코드의 번호 부여·재분류·대규모 구조 변경은 조사, 영향 범위 설명, 사용자 승인 후 별도 작업으로 수행한다.
7. 기존 코드에 대한 정비가 아직 이루어지지 않았다는 이유로 신규 코드의 번호 부여를 생략해서는 안 된다.

## 제6조. 코드 작성과 수정 절차

1. 작업 전에 개발헌법, 이 법률, 프로젝트 지도 및 관련 세부 매뉴얼을 확인한다.
2. 실제 `dev` 코드에서 수정 대상 블록과 호출 관계, 상태값, 데이터 흐름 및 관련 UI 구조를 확인한다.
3. 변경 목적과 범위를 정하고, 기존 블록을 활용할지 새 블록을 만들지 판단한다.
4. 신규 코드가 포함되면 작성 전에 블록 번호의 위치와 계층을 정한다.
5. 사용자의 승인을 받은 범위 안에서만 코드를 작성·수정한다.
6. 코드를 수정한 뒤 블록 번호 주석과 실제 코드 범위가 일치하는지 확인한다.
7. 코드 변경으로 호출 관계, 상태값, 데이터 흐름, 화면 이동 또는 자료 참조가 달라졌는지 점검한다.
8. 관련 매뉴얼이나 프로젝트 관리 문서의 갱신이 필요하면 변경 범위를 제안하고 승인된 범위에서 함께 반영한다.
9. 신규 UI 컨트롤을 만들기 전에는 해당 화면의 외형 표준규격과 기존에 정의된 UI 패턴을 확인한다.
10. 새 컨트롤이 일반 액션 버튼, 텍스트 링크형 클릭 컨트롤, 입력 요소 또는 별도 UI 패턴 중 무엇인지 먼저 구분하고, 해당 규격을 적용하거나 예외 사유를 명시한다.
11. 공통 규격이 자동 적용된다고 가정하지 않는다. 실제 코드의 CSS 선택자·컨테이너 key·컨트롤 key가 적용 대상에 포함되는지 확인한다.
12. 신규 UI 컨트롤의 외형·기능·반응형 동작을 분리해 검토하고, 기존 기능을 재사용할 수 있으면 중복 구현하지 않는다.

## 제7조. 작업 후 필수 검증

신규 코드 작성 또는 코드 수정 작업을 완료하기 전에 다음 항목을 확인한다.

1. 신규로 작성·추가한 기능 코드에 블록 번호가 부여되어 있는가?
2. 새 블록 번호가 기존 번호와 중복되지 않는가?
3. 블록의 계층과 상위·하위 관계가 일관적인가?
4. 블록 번호 주석의 기능 설명과 실제 코드 범위가 일치하는가?
5. 기존 블록 번호와 주석을 승인 없이 변경하거나 삭제하지 않았는가?
6. 신규 기능이 기존 기능·상태값·데이터 흐름에 미치는 영향을 확인했는가?
7. 수정 후 실제 파일을 다시 조회하여 의도한 변경이 반영되었는가?
8. 실행·기능·화면 검증을 수행했다면 실제 확인한 환경과 결과를 구분해 기록했는가?
9. 검증하지 못한 항목과 남은 위험을 완료 보고에 명시했는가?
10. 신규 UI 컨트롤이 관련 외형 표준규격과 정의된 UI 패턴을 사전에 확인하고 적용했는가?
11. 공통 CSS 적용 대상과 실제 컨트롤 key·상위 컨테이너 key가 일치하는가?
12. 클릭형 제목·링크 등 버튼과 다른 UI 패턴을 일반 버튼 규격과 혼동하지 않았는가?
13. PC와 모바일에서 글자 대비, 배경, 줄바꿈, 클릭 영역 및 포커스 표시를 실제 화면으로 확인했는가?

위 항목 중 신규 코드의 블록 번호 부여 여부를 확인하지 못했거나 번호가 누락된 경우에는 작업 완료로 보고하지 않는다.

## 제8조. 완료 보고와 기록

1. 완료 보고에는 변경 파일, 변경한 블록 번호, 주요 변경 내용, 영향 범위 및 검증 결과를 기록한다.
2. 신규 블록을 추가했다면 새로 부여한 번호와 상위 블록과의 관계를 설명한다.
3. 기존 번호를 유지한 경우에도 어떤 기존 블록 안에서 작업했는지 명시한다.
4. 코드 블록 참조가 파일관리 마스터 등 관리 문서에 등록되어야 하는 작업이면 해당 관리 문서의 갱신 필요성을 확인한다.
5. 확인하지 않은 실행 결과나 화면 표시를 검증 완료로 표현하지 않는다.

## 제9조. 적용과 예외

1. 이 법률은 승인되어 적용되는 시점부터 신규 코드 작성과 추가 코드에 적용한다.
2. 긴급한 오류 대응 등으로 사전에 번호 체계를 확정하기 어려운 경우에도 임시로 번호 없이 코드를 남기는 것을 일반적인 예외로 삼지 않는다. 우선 작업을 멈추고 사용자와 처리 방법을 협의한다.
3. 예외 적용이 승인된 경우에는 예외 사유, 대상 코드, 보완할 번호 부여 작업과 완료 시점을 기록한다.
4. 이 법률의 개정·폐기는 개발헌법과 동일하게 사용자의 검토와 승인을 거친다.

## 부칙

1. 본 문서는 코드 수정 작업 원칙 0.1 초안으로 작성한다.
2. 본 문서는 개발헌법의 하위 법률이며, 개발헌법의 개정 없이 개발헌법과 충돌하는 내용을 독자적으로 정할 수 없다.
3. 신규 코드의 블록 번호 부여 의무를 개발헌법 제6장에 명시하는 개정은 별도 검토·승인 절차로 진행한다.
4. 기존 코드의 일괄 번호 부여나 구조 재편은 본 법률의 신규 코드 적용과 분리하여 별도 승인 과제로 관리한다.
