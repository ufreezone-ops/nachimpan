- 관리번호: UI-001
- 상태: **시험 중**
- 적용 기준 브랜치: `dev`
- 마지막 조사: 2026-11-25

## 1. 목적

나침반 앱에서 반복 사용하는 버튼의 외형을 일관되게 관리한다. 현재 기준 디자인은 지하철 2호선 안내판에서 착안한 녹색 테두리의 흰색 캡슐형 버튼이다.

이 문서는 버튼의 공통 시각 규격과 예외 치수를 구분한다. 모든 버튼의 전체 폭·높이·클릭 영역까지 무조건 같게 만드는 문서는 아니다.

## 3. 현재 공통 CSS 적용 대상으로 확인된 버튼

| 연결창 하단 닫기 버튼 | `retirement-connection-close-cta` 내부 `retirement_connection_end` | 문구+패딩+테두리 자동 폭 |

공통 스타일은 네 영역에 같은 테두리·배경·글자·높이·패딩 값을 적용한다. 세 버튼(자료보기 창 연결, 연결창 닫기, 통계 창 연결창으로)의 실제 버튼 폭은 고정하지 않는다. 문구의 글자폭에 공통 좌우 패딩과 테두리가 더해져 자동으로 결정된다. 부동산 적용기준 창 하단 버튼은 별도 배치 규칙이 남아 있으므로 이 세 버튼의 자동 폭 기준과 구분한다.

## 4. 중요한 구분: CSS 선언값과 실제 렌더링 치수

공통 CSS 변수에 같은 값이 선언되어 있다는 사실만으로 실제 브라우저에서 버튼의 바깥 크기·내부 텍스트 영역·클릭 영역까지 같다고 판단하지 않는다.

2026-11-20 사용자 DOM 확인 메모:

- 통계 창의 **‘연결창으로’**: border 상하좌우 6px, padding 상하 4.8px / 좌우 1.6px, 측정 영역 88.813 × 16.805
- 연결창의 **‘닫기’**: border 상하좌우 6px, padding 상하좌우 5.6px, 측정 폭 41px

위 값은 사용자가 개발자 도구에서 확인한 측정 메모이며, 측정 대상이 버튼 외곽인지 내부 요소인지 및 브라우저의 실제 박스 모델을 다시 대조해야 한다. 공통 CSS의 선언값과 차이가 있으므로 현 단계에서는 버튼 치수 통일이 완료됐다고 기록하지 않는다.

**검증 원칙:** 개발자 도구에서 바깥 `button`, 내부 텍스트 래퍼, 텍스트 요소를 구분해 확인한다. PC와 iPhone에서 각각 실제 표시를 확인하고, CSS 선언값·계산된 값·측정된 박스 크기를 별도로 기록한다.

## 5. 적용 및 수정 원칙

1. 먼저 대상 버튼의 실제 Streamlit key와 DOM 구조를 확인한다.
2. 공통 외형은 공통 CSS 변수를 우선 사용한다.
3. 세 공통 버튼의 폭은 `width: max-content`, `min-width: 0`, `max-width: none`으로 내용에 맞게 자동 결정한다. 고정 폭을 부여하지 않는다.
4. 버튼 그룹의 배치·정렬·간격은 바깥쪽 컨테이너에서 관리하며, 버튼 자체의 폭과 혼동하지 않는다.
5. 예외 규칙은 공통 규격을 무력화하지 않도록 적용 범위를 해당 key로 제한한다.
6. 중복 선택자와 뒤늦게 추가된 덮어쓰기 규칙을 조사한 뒤 수정한다.
7. 기존 버튼의 기능, 콜백, 화면 전환은 외형 변경과 분리해 보존한다.
8. 실제 PC·모바일 검증 전에는 상태를 **확정**으로 변경하지 않는다.



## 5.1 자료 제목형 탐색 링크

연결창의 자료 검색 결과처럼 **자료 제목 자체를 눌러 이동하는 UI**는 공통 캡슐형 버튼과 구분한다.

- 적용 위치: 연결창의 자료실 전체 검색 결과
- 상위 컨테이너 key: `retirement-connection-search`
- 제목 클릭 컨트롤 key: `retirement_connection_search_title_{index}`
- 구현 방식: Streamlit 버튼의 클릭 기능을 사용하되, 화면 외형은 텍스트 링크형으로 별도 지정한다.
- 외형: 배경·테두리·그림자 없이 본문 글자색으로 표시하고, 마우스 오버 및 키보드 포커스에서 녹색 글자와 밑줄로 클릭 가능 상태를 알린다.
- 폭: 번호와 제목 길이에 따라 자동으로 늘어나되 부모 영역을 넘지 않는다. 고정 폭을 사용하지 않고 긴 제목은 줄바꿈하며, 두 번째 줄 이후도 첫 줄 제목 시작 위치에 맞춰 왼쪽 정렬하는 것을 목표 규격으로 한다.
- **현재 구현 상태(2026-11-24):** 최신 CSS 수정 후에도 실제 화면에서 두 번째 줄의 왼쪽 정렬이 적용되지 않는다고 사용자가 확인했다. 따라서 이 항목은 미해결이며, 다음 수정에서는 CSS를 추가 추측하지 않고 실제 DOM 구조와 계산된 정렬·폭을 먼저 확인한다.
- 내용: 자료 마스터 원장의 `display_label`에 해당하는 자료 번호와 제목을 함께 표시한다. 번호와 제목은 하나의 클릭 영역으로 묶는다. 검색 결과 카드, 자료 종류, 원문 발췌, 별도 `자료 열기` 버튼을 함께 반복 표시하지 않는다.
- 기능: 기존 자료 열기 처리, 탐색 이력 추가, source/resource ID 설정, 연결창 닫기 및 rerun 동작을 그대로 재사용한다.
- 구분: 이 링크형 컨트롤에는 2호선형 캡슐 버튼의 테두리·배경·높이·패딩 규격을 적용하지 않는다. 다만 신규 UI 컨트롤로서 이 문서와 코드수정 작업원칙의 사전 확인·화면 검증 절차를 적용한다.

## 5.2 자료실 검색 입력창과 실행 버튼

- 적용 위치: 연결창의 자료실 전체 검색 영역
- 입력창 key: `_retirement_connection_search_query`
- 폼 key: `retirement_connection_search_form`
- 입력창은 앱의 어두운 테마 색상 변수 및 부모의 글자 채움색 상속에 종속되지 않도록 흰색 배경(`#FFFFFF`), 짙은 글자색(`#111827`), 커서색을 입력 요소 자체에 명시한다. placeholder는 읽을 수 있는 중간 회색으로 표시한다.
- 검색어 정규화의 **목표**는 `소득관련`과 `소득 관련`처럼 핵심어의 띄어쓰기 차이에 영향을 받지 않는 것이다. `자료를 찾아줘` 등 검색 요청 문구를 제외하는 현재 정규화 로직은 임시 구현으로만 취급한다.
- **현재 검색 로직 상태(2026-11-25):** 검색사전 기반 다중 의도 검색으로 확장되었다. 인접 토큰 결합형과 공백·문장부호 제거 비교로 복합 개념 띄어쓰기를 보완하고, Q&A 기대자료의 보고서 후보 누락을 마스터 원장으로 보완한다. 사용자가 실제 dev 앱에서 결혼·출산·경력단절 질문의 결과가 개선되고 최대 8개 자료가 표시되는 것을 확인했다. 다만 20개 독립 검증 질문의 일반화 성능, 연결 근거의 정밀도, 다양한 띄어쓰기 쌍은 추가 검증이 필요하다.
- 검색 실행 버튼의 목표 규격은 탭 하단 `다음 →` 버튼과 동일한 색상·글자색·글자 크기·모서리·내부 여백이다. `type="primary"` 지정만으로 동일한 외형이 보장된다고 간주하지 않는다.
- **현재 구현 상태(2026-11-24):** 사용자가 실제 화면에서 자료검색 버튼의 배경색과 글자색이 `다음 →` 버튼과 다르다고 확인했다. 미해결 상태이며, 다음 작업에서는 두 버튼의 실제 DOM과 계산된 CSS 값을 직접 비교해 원인을 확인한다.
- 정렬 목표는 `다음 →` 버튼과 동일한 중앙 정렬이다. 실제 버튼 폭은 문구와 내부 여백에 따라 결정하며, 전체 폭으로 늘리지 않는다. 최소 폭 88px 규칙은 실제 `다음 →` 버튼과 비교해 확인한 뒤 유지 여부를 판단한다.
- 색상·대비 CSS는 해당 검색 폼 내부로 범위를 제한한다.

## 7. 적용 사례 — 부동산 적용기준 창 하단 버튼

- 적용 위치: `🏠 부동산 적용 기준` 대화상자 하단
- 상위 컨테이너 key: `housing-price-dialog-actions`
- 연결 버튼 key: `housing_price_open_connection`
- 닫기 버튼 key: `close_housing_price_stats_dialog`
- 방법 안내 화면의 닫기 버튼 key: `close_housing_price_method_dialog`

### 7.1 배치 및 외형

- `연결`과 `닫기`를 같은 행에 나란히 배치한다.
- 두 버튼은 2호선형 공통 CSS 변수와 공통 버튼 규격을 사용한다.
- 버튼 자체의 폭은 고정하지 않는다. 문구 길이에 따라 자동으로 결정되며, 두 버튼을 담는 바깥쪽 행과 열이 중앙 정렬과 간격을 담당한다.
- 공통 높이 2.4rem, 테두리 6px, 캡슐형 모서리, 흰색 배경, 녹색 테두리, 검정 글자, 14.4px / 850 굵기를 적용한다.
- Hover 배경은 `#E8F5EC`를 사용한다.
- 버튼의 기능·콜백은 외형 규칙과 분리해 보존한다.

### 7.2 종료 방식

이 대화상자는 `@st.dialog("🏠 부동산 적용 기준", width="large", dismissible=False)`로 선언한다. `dismissible=False`가 Streamlit의 기본 우상단 `X` 및 바깥 클릭에 의한 닫기를 비활성화하므로, X를 CSS로 숨기는 방식은 사용하지 않는다. 종료는 하단의 명시적 `닫기` 버튼으로만 수행한다. 정상 종료 시 `_housing_price_dialog_open = False`로 설정하고 `_housing_dialog_view`를 `summary`로 초기화한다. 방법 안내 화면과 지역 통계 누락 화면에서도 별도의 하단 닫기 버튼을 제공한다.

### 7.3 연결 기능 보존

`연결` 버튼은 기존 동작을 유지한다. 부동산 적용기준 창을 닫고, 은퇴 탐색기·연결창 상태를 설정하며, 최초 진입 탭과 `.st-key-housing-price-title-row button` 복귀 위치 및 source ID `6051500-00`을 보존한다.

## 5.3 연결창 DOM/CSS 조사 기록 (2026-11-25)

연결창은 Streamlit 대화상자 내부에 놓인 하위 플랫폼이다. CSS 수정 전에 바깥 대화상자부터 내부 콘텐츠까지 실제 DOM 계층과 계산값을 확인한다.

### 확인된 바깥 계층

    body
    --- div[data-testid="stDialog"]
    --- --- div (실제 대화상자 패널)
    --- --- --- section[role="dialog"]
    --- --- --- --- h2[slot="title"] (연결창 제목)
    --- --- --- --- div.st-emotion-cache-czb38y (연결창 본문)
    --- --- --- --- --- stVerticalBlock (본문 최상위 레이아웃)
    --- --- --- --- --- --- stLayoutWrapper
    --- --- --- --- --- --- --- stLayoutWrapper
    --- --- --- --- --- --- --- --- stVerticalBlock (retirement-connection-platform)
    --- --- --- --- --- --- --- --- --- stVerticalBlock (내부 레이아웃)

이것은 확인한 경로만 나타낸다. 생략된 중간 요소나 아직 확인하지 않은 형제 요소를 추측해 보충하지 않는다. portal과 stFloatingOverlayPortal은 body의 별도 자식이며 stDialog의 부모가 아니다.

### 측정값

측정 당시 뷰포트: 652 × 1462px.

| 요소 | 너비 | 높이 |
|---|---:|---:|
| 실제 대화상자 패널 | 620px | 836.075px |
| section[role=dialog] | 620px | 836.075px |
| 본문 div.st-emotion-cache-czb38y | 620px | 764.075px |
| 본문 최상위 stVerticalBlock | — | 728.075px |
| 두 번째 stLayoutWrapper | 572px | 728.075px |
| stVerticalBlock.st-key-retirement-connection-platform | 572px | 728.075px |

본문 padding은 top 12px, 좌우 24px, bottom 24px이며 box-sizing:border-box. 연결창 플랫폼은 배경 #E8F5EC, 녹색 0.8px 테두리, radius 14px, padding top/left/right 1.92px 및 bottom 2.88px로 확인했다.

플랫폼 내부에는 CSS 주입용 stElementContainer가 있으며 display:none이다. 내부에 Markdown 및 style 코드가 들어 있지만 실제 표시 레이아웃을 차지하지 않는다. 이 요소 다음에 실제 콘텐츠 형제 요소들이 계속 존재한다. stColumn이 포함된 하위 레이아웃도 발견했으나 전체 계층은 아직 조사 중이다.

### 조사 및 수정 원칙

1. Elements의 실제 들여쓰기를 부모·자식 관계의 기준으로 삼는다.
2. 태그나 클래스 이름만 보고 계층을 추정하지 않는다.
3. CSS 주입용 숨김 영역과 실제 콘텐츠 영역을 구분한다.
4. CSS 선언값, Computed 값, 실제 박스 크기를 혼동하지 않는다.
5. 실제 DOM과 CSS 우선순위를 확인하기 전에는 선택자를 추측해 규칙을 추가하지 않는다.
6. DOM 계층과 핵심 Computed 값을 한 번에 수집하는 방법을 마련해 사용자에게 반복 복사를 요구하지 않는다.

## 5.4 연결창 상단 이전·다음 보고서 탐색 카드

이 UI는 2호선형 공통 액션 버튼이나 자료 제목형 링크와 구분되는 **보고서 탐색 카드**다. 번호·자료별 색상·제목 및 좌우 이동 맥락을 함께 전달하며, 클릭하면 기존 탐색 상태를 갱신한다.

### 확인된 DOM 및 실제 측정값 (2026-11-26)

- 상위 플랫폼 key: `retirement-connection-platform`
- 좌측 외곽 클릭 컨테이너: `retirement-top-previous-clickable`
- 우측 외곽 클릭 컨테이너: `retirement-top-next-clickable`

- 실제 버튼 측정: 약 213.4 × 48px

측정 당시 개발자 도구 패널로 페이지 폭이 줄어든 상태였으므로, 뷰포트 385px 측정값을 모바일 기기 기준으로 간주하지 않는다. 이후 iframe 폭 약 539px 상태에서 확인한 값을 기준으로 기록한다.

### 설계 방향 — 시험 중

1. 외곽 컨테이너의 68px 기준 높이와 내부 버튼의 자연 높이를 구분한다.
2. 실제 버튼 높이를 제목 길이와 줄바꿈에 맡기되, 좌우 버튼 폭은 각 열을 채우도록 한다.
3. 번호 원·자료별 색상·읽은 자료 표시 등 동적 표현을 보존한다.
4. 중앙 화살표의 크기·위치와 좌우 카드의 기준선을 함께 조정한다.
5. 버튼의 좌우 정렬은 제목을 왼쪽 기준으로 읽기 쉽도록 유지한다.
6. 이전·다음 클릭 시 탐색 이력, source_id/resource_id, 연결창 닫기 및 rerun 동작을 보존한다.
7. 이 UI에는 2호선형 공통 버튼의 테두리·패딩·높이 규격을 일괄 적용하지 않는다.
