# 개발 법률 관리 마스터

이 문서는 저장소 루트의 `개발 법률/` 폴더에 보관하는 나침반 개발·UI 작업 기준의 **목차이자 관제탑**이다. 개발헌법을 상위 규범으로 하며, 개별 문서는 실제 작업에 적용하는 세부 법률과 규격을 정한다.

> 자료의 분류·연결 관계는 기존 `나침반_자료분류_마스터.csv`가 담당한다. 이 README와 개발 법률은 앱의 설계·UI·코드 수정 기준을 담당한다. 두 체계의 역할을 혼동하지 않는다.

## 1. 운영 원칙

1. 나침반 코드 작업은 시작 전에 이 README에서 해당 작업의 법률·규격을 찾고, 관련 문서를 먼저 확인한다.
2. 법률·규격의 내용과 현재 `dev` 코드가 일치하는지 실제 코드를 확인한다. 문서를 무조건 현재 코드보다 우선하는 정답으로 간주하지 않는다.
3. 기존 코드와 매뉴얼이 다르면 임의로 수정하지 않는다. 차이와 영향 범위를 확인하고 사용자와 처리 방향을 합의한다.
4. 규격을 새로 합의하거나 변경하면 해당 법률·규격을 갱신하고 이 README의 상태·개정 이력도 함께 갱신한다.
5. PC·모바일의 실제 표시를 확인하지 않은 항목은 검증 완료로 표시하지 않는다.
6. 개발 변경은 사용자의 별도 허가가 없는 한 `dev` 브랜치에만 적용한다. `main`은 명시적 허가 없이 수정하지 않는다.
7. CSS를 임시 보정 규칙으로 계속 덧붙이지 않는다. 기존 규칙과 우선순위를 조사하고, 유형별 최종 규격이 한곳에서 관리되도록 정리한다.

## 2. 상태 정의

- **확정**: 설계와 적용 범위가 합의되었고, 필요한 검증까지 마친 기준
- **시험 중**: 설계 방향은 합의되었으나 일부 화면·기기·DOM에서 검증이 남아 있는 기준
- **초안**: 문서의 기본 내용은 작성되었으나 사용자 검토와 확정 절차가 남아 있는 기준
- **개정 예정**: 기존 기준을 재검토하거나 수정하기로 한 기준
- **작성 예정**: 아직 상세 매뉴얼이 작성되지 않은 기준
- **폐기**: 더 이상 적용하지 않는 기준. 과거 이력 확인을 위해 문서는 보존할 수 있다.

## 4. 작업 진행 절차

1. 요청된 요소와 사용자 의도를 확인한다.
2. 이 README에서 관련 법률·규격을 찾고, 해당 문서를 읽는다.
3. `dev`의 실제 코드·DOM 구조·기존 CSS 적용 순서를 조사한다.
4. 매뉴얼과 현재 구현의 차이, 수정 범위, 보존해야 할 동작을 정리한다.
5. 필요한 경우 수정안을 먼저 제시하고 사용자 승인을 받는다.
6. 승인된 범위만 수정하고, 수정 후 코드를 다시 읽어 변경 내용을 검증한다.
7. PC·모바일 실제 화면 검증 결과를 구분해 기록한다.
8. 새로 확정된 기준과 검증 결과를 매뉴얼 및 이 README에 반영한다.

## 5. 기준 충돌 및 변경 관리

- 상위 원칙과 개별 매뉴얼이 충돌하면 임의로 해석하지 않고 충돌 사실을 기록한 뒤 사용자와 우선순위를 정한다.
- 개별 매뉴얼 사이에 중복·상충 규격이 있으면 공통 기준과 예외 기준을 분리한다.
- 코드가 매뉴얼과 다를 때는 코드가 최신이라는 이유만으로 매뉴얼을 자동 폐기하지 않는다. 의도된 변경인지 확인한다.
- 임시 실험값은 확정 규격에 섞지 않고 **시험 중**으로 구분한다.
- 과거 규격을 변경할 때는 변경 이유, 적용 대상, 검증 결과를 매뉴얼의 개정 이력에 남긴다.

## 7. 2026-11-25 연결창 DOM 조사 보완

2026-11-25 연결창 DOM/CSS 조사를 진행했다. 실제 대화상자 바깥 계층과 주요 Computed 측정값을 확보했으나, 플랫폼 내부의 형제 요소 및 stColumn 하위 구조는 아직 미완료다.

- 연결창 제목 글자색, 검색 입력창·버튼의 가로 배치와 버튼 외형, 결과 건수·연결 근거, 읽은 자료·추천 자료 구분 제목은 실제 화면에서 미해결 항목으로 확인됐다.
- 모바일 스와이프는 실기기 검증 전이다.
- DOM의 실제 들여쓰기와 Computed 값을 기준으로 CSS 우선순위를 조사한 후 수정한다. 선택자를 추측해 CSS를 누적하지 않는다.
- 검색 결과 최대 8건 정책은 유지한다. 한 화면에 3~4건 표시 및 나머지 스크롤 방식은 검토안이며 확정 규격이 아니다.
- 자세한 계층·치수·조사 원칙은 버튼_외형_표준규격.md의 5.3절과 개발_진행_인수인계.md를 참조한다.
